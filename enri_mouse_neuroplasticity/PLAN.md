# План программной реализации eNRI

## 1. Цель расчёта

По экспериментальным данным требуется найти вектор весов

\[
\mathbf w=(w_1,\ldots,w_{35})^{\mathsf T},
\]

задающий экспериментальный индекс нейропластичности живого состояния

\[
eNRI(\mathbf x)
=
1+
\mathbf w^{\mathsf T}
\left(
\mathbf x-\overline{\mathbf x}_{PBS^{0}}
\right).
\]

Здесь \(\mathbf x\) — стандартизованный вектор из 35 функциональных признаков. Шкала фиксируется условием

\[
\overline{eNRI}_{PBS^{0}}=1,
\]

а смерть задаётся отдельно:

\[
eNRI(death)=0.
\]

Принадлежность к экспериментальной группе не входит в \(\mathbf x\). Группы используются только для построения равенств и неравенств, задающих слабое обучение индекса.

## 6. Сформировать маски экспериментальных состояний

Не хранить состояние только одним категориальным столбцом, поскольку одна и та же мышь может одновременно входить в множество \(LPS^{16}\) и в подмножество \(run^{16}\) или \(MCC^{16}\).

В states.py реализовать функцию

~~~python
get_state_mask(df, state_name) -> boolean mask
~~~

для следующих множеств.

### 6.1. Основные состояния

- \(PBS^{0}\): week = 0 и исходная ветвь PBS;
- \(LPS^{0}\): week = 0 и исходная ветвь LPS;
- \(PBS^{16}\): week = 16 и PBS;
- \(LPS^{16}\): week = 16 и все животные исходной LPS-группы;
- \(PBS^{24}\): week = 24 и PBS;
- \(LPS^{24}\): week = 24 и конечная ветвь LPS;
- \(run^{24}\): week = 24 и конечная ветвь LPS+run;
- \(MCC^{24}\): week = 24 и конечная ветвь LPS+MCC.

### 6.2. Подмножества до второй рандомизации

Для проверки баланса будущих ветвей использовать финальное назначение животного, но признаки брать до начала соответствующего вмешательства:

- \(run^{0}\): week = 0, исходная LPS-группа, конечная ветвь LPS+run;
- \(MCC^{0}\): week = 0, исходная LPS-группа, конечная ветвь LPS+MCC;
- \(run^{16}\): week = 16, исходная LPS-группа, конечная ветвь LPS+run;
- \(MCC^{16}\): week = 16, исходная LPS-группа, конечная ветвь LPS+MCC.

Перед расчётом вывести размер каждого состояния и проверить его ненулевую мощность.

## 7. Зафиксировать множества ограничений

В config.py записать их буквально как данные программы.

\[
\mathcal E=
\{
(PBS^{0},LPS^{0}),
(LPS^{16},run^{16}),
(LPS^{16},MCC^{16})
\}.
\]

В коде:

~~~python
EQUALITY_PAIRS = [
    ("PBS^0", "LPS^0"),
    ("LPS^16", "run^16"),
    ("LPS^16", "MCC^16"),
]
~~~

### 7.2. Пары порядка

\[
\mathcal O_1=
\{
(PBS^{16},LPS^{16}),
(PBS^{24},LPS^{24}),
(run^{24},LPS^{24}),
(MCC^{24},LPS^{24})
\}.
\]

\[
\mathcal O_2=
\{
(PBS^{0},PBS^{16}),
(LPS^{0},LPS^{16}),
(run^{0},run^{16}),

\}.

\mathcal O_3=

## 8. Обработать пропуски

Основная модель требует полный 35-мерный вектор.

В build_dataset.py:

1. Для каждой строки посчитать missing_count по 35 признакам.
2. Если missing_count = 0, строка допускается в основную оптимизацию.
3. Если week = 24 и животное умерло, не считать отсутствие функциональных данных обычной неполнотой наблюдения.
4. Если животное живо, но missing_count > 0, строку исключить из основной complete-case оптимизации и записать в missingness_report.csv.
5. Не выполнять глобальное заполнение медианой.
6. Для каждого состояния вывести:
   - число всех наблюдений;
   - число полных 35-мерных наблюдений;
   - число исключённых из-за частичных пропусков.

Создать observations_complete.csv только из полных живых наблюдений.

Перед продолжением проверить, что для каждого состояния, используемого при вычислении ковариационной матрицы, осталось не менее двух наблюдений. Если нет, остановить расчёт и пересмотреть стратегию пропусков до запуска QP.

## 9. Организовать кросс-валидацию по мышам

Все временные точки одной мыши должны всегда находиться в одной части разбиения.

В cross_validation.py:

1. Сформировать таблицу уникальных mouse_id.
2. Для стратификации использовать конечную ветвь Group_24: PBS, LPS, LPS+run, LPS+MCC.
3. Начать с 4-fold StratifiedGroupKFold с shuffle=True.
4. Повторить разбиение для нескольких random_state, например 25 независимых повторов.
5. Для каждого fold получить train_mouse_ids и valid_mouse_ids.
6. Только после этого разделить observations_complete.csv.

Нельзя сначала делить отдельные строки 0/16/24, поскольку это приведёт к утечке информации одной мыши между train и validation.

## 10. Стандартизовать признаки внутри каждого fold

Исходные значения обозначаются

\[
\mathbf r=(r_1,\ldots,r_{35})^{\mathsf T},
\]

стандартизованные —

\[
\mathbf x=(x_1,\ldots,x_{35})^{\mathsf T}.
\]

Для каждого признака:

\[
x_j=\frac{r_j-m_j}{s_j}.
\]

В standardize.py:

1. Использовать только train rows.
2. Для каждого из 35 признаков вычислить \(m_j\) как среднее по всем полным живым train-наблюдениям недель 0, 16 и 24.
3. Вычислить \(s_j\) как выборочное стандартное отклонение на тех же train-наблюдениях.
4. Если \(s_j=0\), завершить fold с диагностической ошибкой: такой признак не может участвовать в стандартизации.
5. Преобразовать train.
6. Теми же \(m_j,s_j\) преобразовать validation.
7. Сохранить параметры стандартизации текущего fold.

Не стандартизовать отдельно по неделям и не стандартизовать отдельно по группам.

## 11. Вычислить статистики состояний на train

В statistics.py реализовать:

~~~python
compute_state_mean(X, mask) -> xbar_A
compute_state_cov(X, mask) -> S_A
compute_difference(xbar_A, xbar_B) -> d_AB
~~~

Для каждого используемого состояния \(A\):

\[
\overline{\mathbf x}_A
=
\frac{1}{|A|}
\sum_{\mathbf x\in A}\mathbf x,
\]

\[
\mathbf S_A
=
\frac{1}{|A|-1}
\sum_{\mathbf x\in A}
(\mathbf x-\overline{\mathbf x}_A)
(\mathbf x-\overline{\mathbf x}_A)^{\mathsf T}.
\]

Для каждой пары из \(\mathcal E\cup\mathcal O\):

\[
\mathbf d_{AB}
=
\overline{\mathbf x}_A-\overline{\mathbf x}_B.
\]

Проверки:

- размер \(\overline{\mathbf x}_A\): (35,);
- размер \(\mathbf S_A\): (35, 35);
- \(\mathbf S_A\) симметрична с численной точностью;
- все элементы конечны;
- размер \(\mathbf d_{AB}\): (35,).

## 12. Построить матрицу квадратичной формы

Для фиксированных \(\beta>0\) и \(\lambda>0\):

\[
\mathbf Q=
\sum_{A\in\mathcal G}\mathbf S_A
+
\beta
\sum_{(A,B)\in\mathcal E}
\mathbf d_{AB}\mathbf d_{AB}^{\mathsf T}
+
\lambda\mathbf I.
\]

В qp.py:

~~~python
build_Q(state_covs, equality_diffs, beta, lam) -> Q
~~~

После построения:

1. Симметризовать численно:
   \[
   \mathbf Q\leftarrow(\mathbf Q+\mathbf Q^{\mathsf T})/2.
   \]
2. Проверить собственные значения.
3. При \(\lambda>0\) минимальное собственное значение должно быть положительным с учётом численной погрешности.
4. Записать condition number \(\mathbf Q\) в диагностику.

## 13. Зафиксировать margin и переменные послабления

Использовать

\[
\rho=1.
\]

Для каждой пары \((A,B)\in\mathcal O\) вводится отдельная переменная

\[
\eta_{AB}\ge0.
\]

Условие порядка:

\[
\mathbf w^{\mathsf T}\mathbf d_{AB}
\ge
1-\eta_{AB}.
\]

\(\eta_{AB}=0\) означает выполнение требуемого единичного отступа. Чем больше \(\eta_{AB}\), тем сильнее данные заставляют ослабить соответствующее ограничение.

## 14. Реализовать QP в CVXPY

Для одного train-набора и одной тройки \((\beta,\lambda,C)\):

1. Построить \(\mathbf Q\).
2. Создать
   \[
   \mathbf w\in\mathbb R^{35}.
   \]
3. Пусть \(K=|\mathcal O|\). Создать
   \[
   \boldsymbol\eta\in\mathbb R^K,\qquad \boldsymbol\eta\ge0.
   \]
4. Сформировать целевую функцию
   \[
   \mathbf w^{\mathsf T}\mathbf Q\mathbf w
   +
   C\sum_{k=1}^{K}\eta_k.
   \]
5. Для каждой пары порядка \(k\) добавить
   \[
   \mathbf w^{\mathsf T}\mathbf d_k
   \ge
   1-\eta_k.
   \]
6. Для каждого полного живого train-наблюдения добавить положительность
   \[
   1+
   \mathbf w^{\mathsf T}
   \left(
   \mathbf x_i-\overline{\mathbf x}_{PBS^{0}}
   \right)
   \ge\varepsilon.
   \]
7. На первом этапе взять
   \[
   \varepsilon=10^{-3}.
   \]
8. Решить задачу OSQP.
9. Допустимые статусы: optimal или optimal_inaccurate с последующей проверкой остатков.
10. Если задача не решена, сохранить параметры и диагностическое сообщение; не подставлять нулевые веса автоматически.

Скелет:

~~~python
w = cp.Variable(35)
eta = cp.Variable(K, nonneg=True)

objective = cp.quad_form(w, Q) + C * cp.sum(eta)

constraints = []
for k, d in enumerate(order_diffs):
    constraints.append(w @ d >= 1 - eta[k])

for x_i in X_train:
    constraints.append(
        1 + w @ (x_i - xbar_pbs0) >= epsilon
    )

problem = cp.Problem(cp.Minimize(objective), constraints)
problem.solve(solver=cp.OSQP)
~~~

После решения обязательно самостоятельно пересчитать все ограничения из найденных чисел, а не доверять только статусу решателя.

## 17. Для каждого fold оценивать модель на validation

В validation нельзя переобучать \(\mathbf w\).

Использовать train-параметры стандартизации и найденный \(\widehat{\mathbf w}\).

На validation заново вычислить групповые средние стандартизованных признаков только из validation-мышей. Для каждой доступной пары получить

\[
\mathbf d_{AB}^{val}
=
\overline{\mathbf x}_A^{val}
-
\overline{\mathbf x}_B^{val}.
\]

Рассчитать следующие метрики.

### 17.1. Нарушение порядка

Для каждой пары:

\[
h_{AB}
=
\max
\left(
0,
1-
\widehat{\mathbf w}^{\mathsf T}
\mathbf d_{AB}^{val}
\right).
\]

Сохранить:

- mean_order_hinge;
- max_order_hinge;
- долю пар с \(h_{AB}=0\);
- долю пар хотя бы с правильным знаком:
  \[
  \widehat{\mathbf w}^{\mathsf T}\mathbf d_{AB}^{val}>0.
  \]

### 17.2. Ошибка равенств

Для каждой пары из \(\mathcal E\):

\[
e_{AB}
=
\widehat{\mathbf w}^{\mathsf T}
\mathbf d_{AB}^{val}.
\]

Сохранить:

\[
equality\_rmse
=
\sqrt{
\frac{1}{|\mathcal E_{val}|}
\sum e_{AB}^2
}.
\]

### 17.3. Положительность

Для каждого validation-наблюдения:

\[
eNRI_i
=
1+
\widehat{\mathbf w}^{\mathsf T}
\left(
\mathbf x_i-
\overline{\mathbf x}_{PBS^{0},train}
\right).
\]

Сохранить:

- minimum_eNRI;
- число \(eNRI_i<\varepsilon\);
- долю таких наблюдений.

Важно: центр \(\overline{\mathbf x}_{PBS^{0},train}\) остаётся train-центром, поскольку он является частью обученной функции.

### 17.4. Внутригрупповой разброс

Для каждого validation-состояния с достаточным числом наблюдений вычислить дисперсию eNRI. Сохранить среднее и максимум этих дисперсий.

## 18. Правило выбора \(\beta,\lambda,C\)

Не выбирать параметры по качеству на train.

Для каждой комбинации агрегировать validation-метрики по всем fold и повторениям.

Использовать следующий порядок отбора:

1. исключить комбинации с систематическими нарушениями положительности;
2. среди оставшихся минимизировать median mean_order_hinge;
3. при близком результате предпочесть меньший equality_rmse;
4. затем предпочесть меньший внутригрупповой разброс;
5. при практически одинаковом качестве предпочесть решение с меньшей нормой \(\|\mathbf w\|_2\) и более устойчивым направлением весов между fold.

Для устойчивости направления между fold вычислять cosine similarity между векторами весов. Сохранять медиану и нижний квартиль cosine similarity.

Все результаты записывать в hyperparameter_search.csv. Выбор финальной тройки параметров должен быть воспроизводим из этой таблицы.

## 19. Обучить финальную модель

После выбора \((\beta^\*,\lambda^\*,C^\*)\):

1. Взять все доступные полные живые наблюдения.
2. По ним вычислить финальные \(m_j,s_j\).
3. Стандартизовать все живые наблюдения.
4. Построить все состояния.
5. Вычислить \(\overline{\mathbf x}_A\), \(\mathbf S_A\), \(\mathbf d_{AB}\).
6. Построить \(\mathbf Q\).
7. Решить QP с \(\beta^\*,\lambda^\*,C^\*\).
8. Получить
   \[
   \widehat{\mathbf w}
   =
   (\widehat w_1,\ldots,\widehat w_{35})^{\mathsf T}.
   \]
9. Сохранить weights.csv со столбцами:
   - feature;
   - weight;
   - abs_weight;
   - rank_abs_weight.
10. Сохранить параметры стандартизации вместе с весами.

## 20. Рассчитать eNRI

Для каждого полного живого наблюдения:

\[
eNRI_i
=
1+
\widehat{\mathbf w}^{\mathsf T}
\left(
\mathbf x_i-
\overline{\mathbf x}_{PBS^{0}}
\right).
\]

Создать enri_values.csv:

- mouse_id;
- week;
- group_16;
- group_24;
- eNRI.

Смерть не вычислять через линейную формулу. Для состояния death используется определение

\[
eNRI(death)=0.
\]

## 22. Выполнить bootstrap по мышам

В bootstrap.py:

1. Выбирать 56 mouse_id с возвращением.
2. Для выбранной мыши включать все её доступные временные точки.
3. Повторять весь расчёт стандартизации и финального QP.
4. Гиперпараметры \((\beta^\*,\lambda^\*,C^\*)\) не подбирать заново внутри каждого bootstrap — использовать уже выбранные.
5. Выполнить не менее 500 успешных bootstrap-итераций; при достаточном времени — 1000.
6. Для каждой итерации сохранить 35 весов.
7. По каждому признаку вычислить:
   - медиану веса;
   - 2.5% и 97.5% квантили;
   - долю положительных значений;
   - долю отрицательных значений;
   - частоту смены знака относительно финального веса.

bootstrap_weights.csv должен позволять определить, какие веса устойчивы, а какие зависят от конкретного состава выборки.

## 24. Последовательность реализации

Программировать именно в этом порядке:

1. config.py — признаки, пары \(\mathcal E\), пары \(\mathcal O\), константы.
2. load_data.py — чтение Excel и проверки схемы.
3. build_dataset.py — длинный формат и отчёт по пропускам.
4. states.py — маски всех состояний.
5. standardize.py — fit/transform без утечки validation.
6. statistics.py — \(\overline{\mathbf x}_A\), \(\mathbf S_A\), \(\mathbf d_{AB}\).
7. qp.py — построение \(\mathbf Q\) и один запуск CVXPY.
8. Выполнить smoke test при \(\beta=\lambda=C=1\).
9. diagnostics.py — проверка ограничений и таблицы результатов.
10. cross_validation.py — fold по mouse_id.
11. Реализовать сокращённый поиск \(\{0.1,1,10\}^3\).
12. Проверить логику выбора гиперпараметров.
13. Запустить полную сетку.
14. Обучить финальную модель на всех данных.
15. bootstrap.py — устойчивость весов.
16. main.py — объединить pipeline.
17. run.sh — установка зависимостей и запуск main.py.
18. .run — использовать только для запуска через общий GitHub Actions workflow после того, как локальный pipeline полностью проверен.
